# 安全变更与发布检查表

> 最后核验：2026-08-26。本文是门禁，不是发布授权。

## 变更前

- 定位入口、调用方、被调用方、当前态、历史、配置和回调。
- 检查工作区现有改动，保留无关文件。
- 明确 MySQL/Mongo/OSS/Redis、SQL/脚本与 api-test 范围。
- 为状态、字段转换和幂等补回归测试；复杂重构先锁定行为。

## 实现中

- 保持最小改动面；复用现有策略/Handler/Convert。
- Schema 变更给出前置检查、执行、回滚/补偿和后置验证。
- API 兼容旧调用方；新增字段考虑双向序列化和存储 round-trip。
- 外部调用与事务分离，失败保留可重试证据。
- 配置默认值要兼容未配置租户。

## 验证与发布

- 目标测试、编译、静态检查按风险执行并记录真实结果。
- api-test 检查响应、数据库当前态、历史、任务和后继动作。
- 发布 SQL/配置/脚本按明确顺序，不能把测试脚本当生产 DDL。
- 回滚不仅回代码，还要考虑新写数据、外部副作用和已发消息。
- 监控首批流量的失败率、任务积压、回调延迟和状态漂移。

## 证据与未知项

来源：`doc/agent-development-guidelines.md`、SQL/task-pack/solutions、POM/tests、各模块验证边界。实际发布平台、审批和监控阈值当前代码无法确认。面试追问：零停机 schema 演进、向后兼容、回滚与补偿差别。

## 按改动类型追加门禁

| 改动 | 必查范围 | 发布后证据 |
| --- | --- | --- |
| API/DTO 字段 | 调用方、序列化、Convert、Mongo/MySQL round-trip | 旧请求兼容、详情回显、OpenAPI 客户端 |
| 状态/回调 | 枚举、守卫、Handler、历史、重复/乱序 | 终态不回退、后继任务、失败可重试 |
| 配置/账号 | 读取点、默认值、缓存、未配置租户 | 命中策略、缓存刷新、灰度租户 |
| SQL/索引 | 实体/Mapper、存量数据、锁表时间、回滚 | 行数、索引、慢查询、应用错误率 |
| Job/重试 | 扫描条件、批量大小、并发、外部副作用 | 积压、最老任务、重复事实、耗时 |
| 脚本 | key 解析、输入输出、租户范围、沙箱 | 审计记录、命中数量、可逆结果 |

代码回滚不能撤回已提交的官网操作、邮件或 FMS 推送。涉及外部副作用时，发布方案应同时说明“停止继续产生副作用”和“如何补偿已产生副作用”。

## 最小交付证据

交付说明至少包含修改文件、行为边界、执行过的命令和退出结果、未覆盖项、SQL/配置/脚本顺序、回滚/补偿和首批监控指标。未运行的验证使用“未执行/被阻塞”，不能使用模糊的“应该没问题”。
