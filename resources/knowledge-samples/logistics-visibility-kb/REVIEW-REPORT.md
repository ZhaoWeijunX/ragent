## 1. 审查目标与方法

本轮审查不只检查 Markdown 是否能打开，还按“新人不看源码也能理解核心设计”的标准检查主题完整性、源码依据和信息密度。审查分为四层：

1. 结构审查：文件编号、文件名、frontmatter title、唯一 H1、H2 层级、代码围栏、Mermaid 块和相对链接。
2. 内容审查：每篇是否覆盖功能背景、核心代码、完整流程、实现原理、方案原因、技术细节、异常或并发边界、问题与优化方向。

4. 独立复审：把分目录文档交给另一审查任务检查标题、编号、格式、篇幅、无效内容和源码事实。复审发现的问题由主任务修正后重新执行硬审计和源码核对。

## 4. 审查中发现并修复的问题

### 4.1 篇幅和信息密度

初稿中有 15 篇低于 800 个中文汉字。已围绕各自项目实现补充排查步骤、边界条件和证据说明，而不是复制通用原理。最终最短文档也达到 805 个中文汉字，未发现 80 字以上的完全重复正文段落。

### 4.2 标题、编号和链接

独立复审发现 4 个文件名主题与 H1 不完全一致。相关文件已重命名并同步修复 INDEX、上一篇/下一篇链接。审计脚本进一步增加“归一化文件名必须等于 H1”“每篇必须且只能被 INDEX 收录一次”“INDEX 链接文字必须等于 H1”检查，最终全部通过。

### 4.3 类与方法引用

审查期间修正了 3 处方法名偏差：JobEnd 状态消息、船司状态配置查询和 Admin 手工发送 Schedule MQ。最终自动扫描到 37 组显式 `类#方法` 引用，类文件与方法声明均可在七个当前检出项目中定位，未发现缺失项。

### 4.4 强制融合去重与漏桶

独立复审指出，初稿错误地把 pending ZSET 和 `FusionLeakyBucketImpl` 描述成持续出队的后台 worker。当前文档已按源码改为：`tryAcquire` 通过 Lua 原子检查 sent/pending 并写 pending；`tryEnter` 只计算 `waitMs`；`TriggerFusionCleanHandler` 随即调用 `sendMixDataMqByApiForForce(..., waitMs)` 投递延迟 MQ；投递成功后 `confirmSent`，异常时 `releasePending`。文档同时明确了 Redis 与 MQ 不构成事务、进程在投递前崩溃时 pending 不会被后台自动补发等真实边界。

### 4.5 状态映射热点路径

独立复审指出，初稿把两个 `ctnrStatusMapping` 重载的优化方向写反。当前文档已按 `HeaderMappingImpl` 修正：两参数重载仍在嵌套循环内重复 `replaceAll`；带两个 boolean 参数的四参数重载会预先展开和归一化规则。文档也补充了当前实现使用无序 Set、可能原地修改规则对象、空配置直接返回以及多个规则命中时结果顺序不稳定等风险，不再声称已经使用预编译 Pattern 或保留“空配置异常语义”。

## 6. 当前仍存在的限制与非阻断问题

1. **运行态未验证。** 本次是当前 checkout 的源码静态分析，没有启动七个服务，也没有连接 Nacos、RocketMQ、Redis、MySQL、Mongo、SLS、中台鉴权或外部采集商。因此线上 Topic、消费组、限流参数、数据规模和故障恢复效果仍应以部署环境为准。
2. **Mermaid 未实际编译。** 本机没有可用的 Mermaid CLI；目前只检查代码块存在、围栏配对和可读的静态结构，不能保证所有知识库渲染器都能无差异渲染。
3. **部分外部消费者不在仓库范围。** 外部采集器、部分 DataPush 消费端、中台用户权限来源和生产告警平台不在本次七个项目中；文档已使用“当前代码无法确认”标记，未补造结论。
4. **源码引用以短类名为主。** 37 处关键引用可自动定位，但正文并非每一处都写绝对路径和行号。这样更利于阅读、对代码移动也更稳定；后续若接入专用知识库平台，可生成按 commit 固定的源码跳转索引。
5. **检出版本并非全部与远端同步。** 审查时 `iscm-trace-sf-data-mix` 比跟踪分支落后 3 个提交，`iscm-trace-admin-web` 落后 1 个提交且存在用户已有的 `vite.config.ts` 修改。知识库描述的是本地当前代码快照，未擅自拉取、覆盖或修改这些项目。
6. **独立增量复核受工具策略限制。** 独立复审在修订前给出 `REVISE` 并定位两项 HIGH；主任务修复后，向同一复审任务发送内部路径和实现摘要的增量复核请求被策略拒绝。最终 PASS 依据是主任务对相同源码的逐行复核、37 组引用定位和 0 错误/0 警告硬审计，不把未执行的跨任务增量复核写成已通过。
